## Design decision

Выбран named type `MemoryAddressRegister`, реализованный наследованием от `FixedWidthRegister`.

MAR является самостоятельным component boundary, потому что закрепляет уникальные invariants:

- width всегда 12;
- reset value всегда `0x000`;
- constructor не принимает configurable width или reset value;
- `load`, `reset`, `value` и strict validation переиспользуются без переопределения.

Named type полезнее A/B wrappers: MAR имеет отдельную аппаратную ответственность как storage текущего SRAM address и позднее участвует в address-path integration tests. Source selection остаётся вне MAR: модель не выбирает PC или IR operand, не декодирует `ADDR_SEL` и принимает уже выбранное 12-bit значение через `load()`.

## Public API

```python
mar = MemoryAddressRegister()
mar.load(0xABC)
current = mar.value
mar.reset()
```

## Tests

Проверены:

- width `12`, reset `0x000` и initial value `0x000`;
- отсутствие configurable constructor parameters;
- valid addresses `0x000`, `0x001`, `0x7FF`, `0x800`, `0xFFF`;
- invalid `-1`, `0x1000`, `True`, `False`, неподходящий тип;
- `InvalidComponentValue`, error context и сохранение state после failed load;
- детерминированный reset;
- изоляция двух MAR instances.
