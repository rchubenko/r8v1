# Task M2-011: Implement ADD

## Summary

Добавлено atomic ADD execution после fetch. ADD читает актуальный byte из state-owned SRAM по полному 12-bit operand, переиспользует approved stateless ALU и загружает результат в A с полностью определёнными FLAGS.

## Scope

В scope входят только ADD execution после supplied `DecodedInstruction`, full 12-bit SRAM addressing, modulo-256 result, Z/C/S/O update и preservation остальных architectural fields. SUB, STA, branches, HALT, dispatcher, microsteps и hardware execution не реализуются.

## Design decision

`ArchitecturalState.execute_instruction()` получил отдельную ветку `Opcode.ADD`:

```text
operand_value = SRAM.read(instruction.operand)
alu_result = evaluate(ALUMode.ADD, A, operand_value)
A <- alu_result.result
FLAGS <- latch_flags_for_alu_write(alu_result)
```

Используется unified stateless ALU из `cpu/`. Arithmetic, modulo-256 result, carry, zero, sign и signed overflow не дублируются в `emulator/`. Persistent B register, `ALU_MODE` decode, `control word` и physical B-load sequence отсутствуют.

## FLAGS behavior

После ADD сохраняются значения approved ALU:

- Z определяется из modulo-256 result;
- C определяется unsigned carry out;
- S определяется bit 7 result;
- O определяется signed overflow для ADD.

`latch_flags_for_alu_write()` устанавливает `flags_defined_mask = Z | C | S | O` независимо от предыдущего mask и concrete FLAGS.

## State preservation

После fetch ADD изменяет только A и FLAGS/mask. PC остаётся post-fetch, IR и SRAM сохраняются, HALT не изменяется. Operand byte читается из SRAM при каждом execution и не кэшируется.

## Tests

Проверены:

- boundary result cases, включая zero, carry, sign и wraparound;
- carry при no-carry, carry с non-zero result и maximum operands;
- signed overflow и отсутствие overflow на representative cases;
- Z/S для zero, positive, sign-bit и wraparound results;
- все пары `A = 0x00..0xFF` и operand byte `0x00..0xFF` через emulator execution boundary, всего `256 x 256` combinations;
- все initial `flags_defined_mask` variants: none, Z/S, C/O и all defined;
- full 12-bit operand addresses `0x000`, `0x001`, `0x0FF`, `0x100`, `0xABC`, `0xFFE`, `0xFFF`;
- current SRAM value при repeated ADD после изменения memory;
- PC/IR/SRAM/HALT preservation;
- ADD instruction fetch boundary `0xFFF -> 0x000` с post-fetch PC `0x001`;
- NOP, LDI и LDA regression, а также unsupported SUB rejection without mutation.
